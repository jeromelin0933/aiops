## 3. Architecture and metrics topology

目前 metrics deployment topology：

```text
Metrics Generator
  → host exporter :8000
  → Prometheus container scrape target host.docker.internal:8000
  → Grafana
```

Metrics Generator 提供四個 Gauge：

| Metric |
|---|
| `system_memory_usage_pct` |
| `api_p95_latency_ms` |
| `api_requests_per_sec` |
| `db_pool_active_connections` |

目前 `api_requests_per_sec` 是 single series；四個 Gauge 均未使用 dynamic scenario、service 或 detector labels。這些是 current implementation / deployment reality，不是新的 detector normative contract。

整體產品方向可高階表達為Logs／Metrics → Event Detection → downstream Alert Correlation → Incident → RCA → operational／presentation interfaces。SPEC-006 Policy Engine與SPEC-007 Correlation State已實作；SPEC-008～011、完整Alert Correlation Runtime、Dashboard、Jira、Discord／ChatOps與Email fallback仍pending。PRD-003 v1.0 Final持續定義correlation／Incident detailed requirements；DDS-001不是該domain的design authority。

## 4. Log path and Promtail / Loki boundary

目前 log pipeline 的 host 與 container path 明確如下：

```text
Host physical log:  logs/aiops.json.log
Compose mount:      ./logs:/var/log/aiops
Promtail reads:     /var/log/aiops/*.log
Loki push endpoint: http://loki:3100/loki/api/v1/push
```

`logs/aiops.json.log` 與 `./logs` 是 host-relative path；`/var/log/aiops/*.log` 是 Promtail container 內的 path。此處僅記錄既有 deployment configuration。

## 5. Grafana deployment state

Grafana container 可由目前 Compose definition 啟動，但 service started 不等於 dashboard ready。目前操作邊界為：

- Prometheus datasource 需人工建立。
- Loki datasource 需人工建立。
- `docker/grafana/dashboard.json` 需人工 import，並選擇對應 datasource。
- Repository 尚未提供完整 datasource / dashboard auto provisioning。

這是現況說明，不新增 automation requirement，也不表示 dashboard 已自動完成配置。
